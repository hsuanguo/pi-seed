# Source and compatibility notes

This skill adapts the creation, evaluation, grading, and improvement workflow of [S1M0N38/pi-skill-creator at a28b3b4a2f24218231725cb013e2aa68309361d8](https://github.com/S1M0N38/pi-skill-creator/tree/a28b3b4a2f24218231725cb013e2aa68309361d8). The upstream license file is Apache-2.0 despite its README stating MIT; the included `LICENSE.txt` preserves the source license. Modified instructions are marked in their files. Helpers are new pi-seed implementations, replacing upstream's inline testing and CLI description optimizer.

Checked against pi's pinned development dependency **1.0.0** and pi-subagents **0.76.1**, both the npm distribution and [source at 5da808168c097ea0d56616644773efe0f6f87938](https://github.com/nicobailon/pi-subagents/tree/5da808168c097ea0d56616644773efe0f6f87938). The local global pi executable was 1.0.3; the repository checks use 1.0.0. No installed pi-subagents was found in this execution environment. `setup/settings.json` declares `npm:pi-subagents` without a version, so verify the user's installed guide before dispatch.

Offline validation used real Pi faux-model sessions for explicit skill loading and a fresh baseline. A separate probe against the downloaded pi-subagents source created and deleted the generated project profile, resolved its private skill snapshot, built the actual plugin prompt, and verified that a Pi child could read the selected file while the baseline had no skill metadata. This validates those interfaces without credentials or paid model calls; it does not measure model quality or exercise background dispatch.

Controlling source paths:

- Pi `packages/coding-agent/src/core/resource-loader.ts`: `noSkills` retains explicit skill paths; `skillsOverride` controls the final catalog, including skills contributed by extensions. `noContextFiles` suppresses context-file loading. See [official skills documentation](https://pi.dev/docs/latest/skills) for discovery and on-demand loading.
- pi-subagents [`src/agents/skills.ts`](https://github.com/nicobailon/pi-subagents/blob/5da808168c097ea0d56616644773efe0f6f87938/src/agents/skills.ts): `resolveSkills` searches agent-local `skillPath` first, then falls back to normal discovery. Local `SKILL.md` names come from directory names. `buildSkillInjection` advertises metadata/location, not the full body, and filters `disable-model-invocation` skills.
- pi-subagents [`src/runs/foreground/execution.ts`](https://github.com/nicobailon/pi-subagents/blob/5da808168c097ea0d56616644773efe0f6f87938/src/runs/foreground/execution.ts): runtime skill names override profile defaults; unresolved names generally become warnings. Explicit fresh context starts a new session; forks and resumes have different semantics.
- pi-subagents [`src/runs/shared/child-launch.ts`](https://github.com/nicobailon/pi-subagents/blob/5da808168c097ea0d56616644773efe0f6f87938/src/runs/shared/child-launch.ts) and [`child-session.ts`](https://github.com/nicobailon/pi-subagents/blob/5da808168c097ea0d56616644773efe0f6f87938/src/runs/shared/child-session.ts): `inheritSkills: false` sets `noSkills` and an empty `skillsOverride`, while selected skills arrive through the child prompt. Foreground children do not load ambient extensions; registered parent providers remain available.
- pi-subagents [`src/extension/schemas.ts`](https://github.com/nicobailon/pi-subagents/blob/5da808168c097ea0d56616644773efe0f6f87938/src/extension/schemas.ts) and [`src/agents/agent-management.ts`](https://github.com/nicobailon/pi-subagents/blob/5da808168c097ea0d56616644773efe0f6f87938/src/agents/agent-management.ts): runtime `skill` is a name/list/false; profile `skillPath` is configured through management, not a direct dispatch argument. Empty `extensions` disables ambient extensions. Project-scope create/delete persists profile files.

Read the installed `agents` and `tool-reference` guides when applying these mechanisms. Future versions can change the interfaces; these notes are evidence for the checked versions, not a promise about all versions.
